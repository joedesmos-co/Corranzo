# OMR benchmark fixtures

This directory contains the redistributable fixtures used by
`npm run omr:benchmark-dashboard`.

## Enforced CC0 corpus

Ten original fixtures are vendored as deterministic PDF + MusicXML pairs: five
Piano and five Guitar. Their compositions, engravings, truth files, scan
derivatives, metadata, and small benchmark music font are dedicated under
`CC0-1.0`; see `LICENSE-CC0-1.0.txt`.

`provenance.json` is the authoritative per-fixture record. It includes title,
creator, public-domain status, file license, allowed use, attribution, source
formats, instrument, category coverage, scan lineage, and truth-verification
method. A fixture may not be enforced unless that record is complete.

The corpus is generated by:

```bash
python3 scripts/generate-omr-benchmark-corpus.py
```

PDF and MusicXML are built from the same in-memory event model. The PDFs use
ReportLab invariant mode, and the scan noise has a stable fixture-derived seed,
so outputs and checksums are byte-reproducible. The tiny
`font/CorranzoBenchmarkMusic.ttf` maps original geometric glyph outlines to the
SMuFL private-use code points recognized by the vector OMR path. Its source is
`scripts/build-omr-benchmark-font.py`.

## Category coverage

Piano coverage includes clean beginner single staff, grand staff, chords,
multiple voices, ties, slurs, articulations, eighth/sixteenth rhythms, tuplets,
rests, dotted rhythms, repeats, voltas, an image-only scan, a modern vector PDF,
and dense advanced texture.

Guitar coverage includes TAB-only, standard notation only, paired notation and
TAB, double-stops, 3-6-note chord stacks, multi-digit frets, ties/slides/
hammer-ons/pull-offs, sparse and dense layouts, capo/repeat/coda text, an
image-only scan, and vector PDFs.

The scanned paired-guitar fixture has an expected honest-rejection outcome:
without a text layer, exact fret/string and TAB rhythm recovery is unsupported.
Its truth file is still required so future improvements can convert that
rejection into a measured transcription without changing the fixture.

## Legacy local diagnostics

The manifest retains six historical third-party fixtures only as optional,
diagnostic-only inputs. They are never vendored and never enforced. This keeps
local comparison history available without treating an unclear or copyrighted
edition as a redistributable regression fixture.

## Integrity and rules

Verify all enforced assets and checksums without running OMR:

```bash
node scripts/omr-benchmark-dashboard.mjs --check-fixtures
```

- Do not add copyrighted commercial arrangements.
- Do not infer redistribution rights from a free download.
- Do not enforce a fixture without PDF, trustworthy MusicXML, checksum, and a
  complete `provenance.json` record.
- Do not weaken thresholds to make the dashboard pass.
- Do not hardcode fixture titles, coordinates, pages, or measures into runtime
  OMR logic.
